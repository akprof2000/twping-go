# Реализованные форматы на проводе

Справочные заметки по тем частям TWAMP, которые реализует этот клиент, с
указанием используемых смещений байтов. Первоисточники — RFC 4656 (OWAMP) и
RFC 5357 (TWAMP); приведённые ниже раскладки фиксируют, как спецификации
отображаются на октеты в канале, и совпадают с реализацией perfSONAR owamp.

Все многооктетные целые передаются старшим байтом вперёд. Поля `MBZ`
передаются нулевыми.

## Управляющий канал (TCP, порт 862 по умолчанию)

| Сообщение | Направление | Размер | Примечания |
| --- | --- | --- | --- |
| Server-Greeting | сервер → клиент | 64 | Без шифрования |
| Set-Up-Response | клиент → сервер | 164 | Без шифрования |
| Server-Start | сервер → клиент | 48 | В шифрующих режимах последние 16 октетов зашифрованы |
| Request-TW-Session | клиент → сервер | 112 | Команда 5 |
| Accept-Session | сервер → клиент | 48 | |
| Start-Sessions | клиент → сервер | 32 | Команда 2 |
| Start-Ack | сервер → клиент | 32 | |
| Stop-Sessions | клиент → сервер | 32 | Команда 3; двусторонний клиент отправляет одну пару блоков и не читает ответ |

### Server-Greeting

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 12 | Не используется |
| 12 | 4 | Режимы (Modes) |
| 16 | 16 | Challenge |
| 32 | 16 | Salt |
| 48 | 4 | Count (число итераций PBKDF2) |
| 52 | 12 | MBZ |

Биты режимов: `1` открытый, `2` с аутентификацией, `4` шифрованный, `8`
смешанный (только TWAMP — шифрованное управление при тестовых пакетах в
открытом формате).

### Set-Up-Response

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | Режим (ровно один бит) |
| 4 | 80 | KeyID |
| 84 | 64 | Token |
| 148 | 16 | Client-IV |

В шифрующих режимах Token — это результат
`AES-CBC(PBKDF2-HMAC-SHA1(парольная фраза, salt, count, 16), IV=0)`, применённый
к `Challenge (16) || ключ сессии AES (16) || ключ HMAC (32)`.

### Server-Start

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 15 | MBZ |
| 15 | 1 | Accept |
| 16 | 16 | Server-IV |
| 32 | 8 | Uptime (метка времени) |
| 40 | 8 | MBZ |

У третьего блока нет собственного поля с дайджестом: он входит в текст,
покрываемый HMAC следующего сообщения.

### Request-TW-Session

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 1 | Команда = 5 |
| 1 | 1 | IPVN (4 или 6, младшая тетрада) |
| 2 | 1 | Conf-Sender = 0 |
| 3 | 1 | Conf-Receiver = 0 |
| 4 | 4 | Число слотов = 0 |
| 8 | 4 | Число пакетов = 0 |
| 12 | 2 | Порт отправителя |
| 14 | 2 | Порт получателя |
| 16 | 16 | Адрес отправителя |
| 32 | 16 | Адрес получателя |
| 48 | 16 | SID (нулевой: назначает сервер) |
| 64 | 4 | Длина заполнения |
| 68 | 8 | Время начала |
| 76 | 8 | Таймаут |
| 84 | 4 | Дескриптор Type-P |
| 88 | 8 | MBZ |
| 96 | 16 | HMAC |

Для двусторонних сессий число слотов и число пакетов нулевые: клиент формирует
расписание локально из SID. Адрес IPv4 занимает первые 4 октета своего
16-октетного поля, остальное нулевое. При `-Z` оба поля адресов обнуляются для
прохождения NAT.

### Accept-Session

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 1 | Accept |
| 1 | 1 | MBZ |
| 2 | 2 | Порт |
| 4 | 16 | SID |
| 20 | 12 | MBZ |
| 32 | 16 | HMAC |

Значения Accept: 0 принято, 1 внутренняя ошибка, 2 отклонено, 3 не
поддерживается, 4 постоянно недоступно, 5 временно недоступно.

### Шифрование и аутентификация

В режимах с аутентификацией, шифрованном и смешанном управляющий канал
шифруется AES-CBC с одним сцепленным IV на каждое направление в течение всего
соединения: клиент шифрует с `Client-IV`, сервер — с `Server-IV`, оба на ключе
сессии из Token.

Каждое сообщение несёт 16-октетный HMAC в последнем блоке: усечённый HMAC-SHA1
по блокам открытого текста этого сообщения, не считая самого поля дайджеста, на
ключе HMAC из Token. Накапливаемый HMAC сбрасывается после каждого сообщения, но
блок, у которого нет собственного поля дайджеста (блок uptime в Server-Start),
переносится в дайджест следующего сообщения.

## Тестовый канал (UDP)

Размеры полезной нагрузки без учёта заполнения:

| Режим | Пакет отправителя | Отражённый пакет |
| --- | --- | --- |
| Открытый, смешанный | 14 | 41 |
| С аутентификацией, шифрованный | 48 | 112 |

По умолчанию клиент дополняет свои пакеты на разницу этих величин, чтобы ответ
отражателя получался того же размера, что и запрос.

### Пакет отправителя, открытый и смешанный режимы

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | Порядковый номер |
| 4 | 8 | Метка времени |
| 12 | 2 | Оценка погрешности |
| 14 | — | Заполнение |

### Пакет отправителя, режимы с аутентификацией и шифрованный

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | Порядковый номер |
| 4 | 12 | MBZ |
| 16 | 8 | Метка времени |
| 24 | 2 | Оценка погрешности |
| 26 | 6 | MBZ |
| 32 | 16 | HMAC |
| 48 | — | Заполнение |

В режиме с аутентификацией шифруется только первый блок (AES-ECB, что для одного
блока равносильно CBC с нулевым IV), и HMAC покрывает этот единственный блок
открытого текста; блок с меткой времени передаётся открыто. В шифрованном режиме
первые два блока шифруются в CBC, а HMAC покрывает оба блока открытого текста.

### Отражённый пакет, открытый и смешанный режимы

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | Порядковый номер отражателя |
| 4 | 8 | Метка времени отражателя |
| 12 | 2 | Оценка погрешности |
| 14 | 2 | MBZ |
| 16 | 8 | Метка времени приёма |
| 24 | 4 | Порядковый номер отправителя |
| 28 | 8 | Метка времени отправителя |
| 36 | 2 | Оценка погрешности отправителя |
| 38 | 2 | MBZ |
| 40 | 1 | TTL отправителя |

### Отражённый пакет, режимы с аутентификацией и шифрованный

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | Порядковый номер отражателя |
| 16 | 8 | Метка времени отражателя |
| 24 | 2 | Оценка погрешности |
| 32 | 8 | Метка времени приёма |
| 48 | 4 | Порядковый номер отправителя |
| 64 | 8 | Метка времени отправителя |
| 72 | 2 | Оценка погрешности отправителя |
| 80 | 1 | TTL отправителя |
| 96 | 16 | HMAC |

Отражатель сообщает одну оценку погрешности, и она относится к обеим снятым им
меткам времени.

Ключи тестовой сессии вырабатываются из SID, как описано в разделе 4.1 RFC 4656:
SID используется как ключ AES, тестовый ключ AES получается ECB-шифрованием
ключа сессии управляющего канала, а тестовый ключ HMAC — CBC-шифрованием (с
нулевым IV) ключа HMAC управляющего канала.

## Метки времени

Метка времени — 64-битное значение с фиксированной точкой: 32 бита секунд от
эпохи NTP (1900-01-01) и 32 бита дробной части секунды. Сопровождающая её
2-октетная оценка погрешности устроена так:

| Биты | Поле |
| --- | --- |
| 15 | Синхронизировано |
| 14 | MBZ |
| 13-8 | Scale (6 бит) |
| 7-0 | Multiplier |

Оценка в секундах равна `Multiplier * 2^(Scale-32)`. Нулевой множитель означает
недопустимую оценку.

RFC 4656 сохраняет принятый TTL, чтобы вторая сторона могла вывести число хопов;
это работает лишь при том, что отправители выставляют 255, — данный клиент
задаёт исходящий TTL соответственно.

## Расписание отправки

Интервалы между пакетами распределены экспоненциально с заданным средним и
порождаются алгоритмом Кнута 3.4.1.S («Искусство программирования», том 2) над
равномерно распределёнными 32-битными значениями. Источник равномерных значений —
AES в режиме счётчика на ключе из 16-октетного SID, счётчик начинается с нуля, а
из каждого выходного блока последовательно берутся четвёрки октетов. Благодаря
этому обе стороны получают одинаковое расписание из идентификатора сессии.

## Статистика

Для каждого отражённого пакета, где `S` — метки времени отправителя, а `R` —
метки времени отражателя:

| Набор | Определение |
| --- | --- |
| Обработка на отражателе | `R.send - S.recv` |
| Время кругового обхода | `(R.recv - S.send) - обработка` |
| Задержка до отражателя | `S.recv - S.send` |
| Задержка от отражателя | `R.recv - R.send` |

Джиттер в отчёте — это P95 − P50 соответствующего набора. Отрицательные задержки
до или от отражателя означают расхождение часов, и отчёт об этом предупреждает,
поскольку в таком случае осмысленно только значение кругового обхода. Процентили
берутся из гистограммы задержек, размер корзины которой задаётся параметром `-b`.

Порядковый номер, встреченный более одного раза с *другим* номером отражения, —
это дубликат при отправке; повторный приход того же номера отражения — дубликат
при отражении. Дубликаты не учитываются в гистограммах и в числе хопов, но
показываются отдельно.
