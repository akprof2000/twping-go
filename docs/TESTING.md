# Тестирование

## Модульные и сквозные тесты

```bash
go test ./...
go test -race ./...
```

Набор запускает сервер TWAMP и отражатель внутри процесса
(`internal/owamp/reflector_test.go`), поэтому внешний сервер не нужен. Покрыто:

- установление управляющей связи во всех четырёх режимах, включая выработку
  ключей PBKDF2, формирование Token и HMAC каждого сообщения;
- согласование режимов, в том числе случаи неверной парольной фразы и отсутствия
  общего поддерживаемого режима;
- кодирование пакетов отправителя и отражателя для каждого режима;
- учёт потерь, дубликатов при отправке и при отражении, задержка обработки на
  отражателе;
- детерминированность, среднее и стандартное отклонение экспоненциального
  расписания;
- человекочитаемый, машиночитаемый и сырой форматы вывода.

Отражатель умеет вносить сбои, чтобы проверять пути учёта:

| Поле | Действие |
| --- | --- |
| `dropEvery` | Отбрасывает каждый N-й пакет |
| `dupEvery` | Отражает каждый N-й пакет дважды |
| `procDelay` | Задерживает каждое отражение |

## Совместимость и нагрузочные прогоны против настоящего сервера

Каталог `testing/` собирает образ Docker с оригинальным сервером perfSONAR
`twampd` и клиентом `twping` — они компилируются из исходников, поскольку owamp
не входит в пакеты Debian, — рядом с этим клиентом, так что оба работают в
одинаковом окружении.

```bash
cd testing
GOOS=linux GOARCH=amd64 go build -o twping-go ../cmd/twping
docker build -f Dockerfile.owamp -t twamp-ref .
docker network create twamp-net
docker run -d --name twamp-server --network twamp-net twamp-ref
```

Проверка, что оба клиента говорят с одним и тем же сервером:

```bash
docker run --rm --network twamp-net twamp-ref twping    -c 20 -i 0.05 twamp-server
docker run --rm --network twamp-net twamp-ref twping-go -c 20 -i 0.05 twamp-server
```

Сравнение машиночитаемых сводок поле за полем:

```bash
docker run --rm --network twamp-net twamp-ref bash -c \
  'twping-go -c 20 -i 0.01 -L 1 -M twamp-server 2>/dev/null | grep -v "^\t"'
```

Нагрузочное сравнение — пять сценариев от 1 kpps до 5 kpps, по три повтора
каждый, с выводом времени работы, процессорного времени, пикового RSS, потерь и
задержек для обоих клиентов:

```bash
docker run --rm --network twamp-net twamp-ref loadtest.sh twamp-server 3
```

Уборка:

```bash
docker rm -f twamp-server && docker network rm twamp-net
```

Сервер работает в открытом режиме без ограничений по диску и полосе
(`testing/twamp-server.conf`, `testing/twamp-server.limits`), чтобы движок
политик не оказался тем узким местом, которое мы измеряем. Тестовые порты
зафиксированы в диапазоне 8760-8960, так что его можно опубликовать, если нужно
достучаться до сервера извне сети Docker.

Измеренные результаты сведены в [README](../README.md#измеренные-результаты).

## Как читать результаты нагрузочных прогонов

- Отражатель обрабатывает пакеты последовательно. При пуассоновском расписании
  часть промежутков оказывается заметно короче среднего, поэтому на высоких
  скоростях внутренняя очередь отражателя проявляется как *задержка до
  отражателя*, а не как время обработки. Чтобы выделить именно время обработки,
  используйте расписание с фиксированным слотом.
- Сетевой мост Docker добавляет один хоп. Число хопов считается относительно
  исходящего TTL 255, поэтому один переход через мост читается как `хопов = 0` со
  стороны отражателя, если отражатель тоже выставляет 255.
- Поскольку по умолчанию локальные часы не объявляются синхронизированными, этот
  клиент печатает `(без синхронизации)`, и оценки погрешности однонаправленных
  задержек отличаются от значений клиента на C, который читает состояние NTP в
  ядре. Для прямого сравнения этих величин используйте `--sync` или
  `--esterror`.
